# Acceptance evidence and qualification boundary

This is a sanitized deployment-level account, not raw transcripts, media, task IDs, credentials or a transferable certification. The portable package and its inactive defaults must be qualified on each new installation.

## Observed on the owner's Linux deployment
- Actual reel acquisition; local timestamped speech plus sampled-frame visual evidence, honest partial coverage and repeated-link reuse.
- Native optional Instagram naming: 64 targeted gateway tests plus fresh Discord thread/reply/reload verification. The patch manifest records the exact base and bundle hash; this repo CI parses the patch but does not execute Hermes's gateway tests.
- Earlier actual approved reviewer task completed and returned to its original source thread.
- Revised automatic-review/general-learning integration exercised with an explicitly synthetic text passage: Scout native task creation, exact subscription, separate Default worker completion, attributed learning note, actual same-thread notification/reply, no forced skill proposal or install. Repeating the same key reused the completed task with one worker run.
- Actual fixture cleanup deleted three eligible files while preserving all 35 protected fixture files and all 33 real-library payloads. Cases covered recent, pinned, active extraction/review, unknown dates, nested fresh transcript, symlink, traversal and malformed JSON. No personal source material is included here.
- Production bounded cleanup then ran successfully with zero expired candidates and zero real deletions.

## Not established by those results
Actual provider-quota outage/restart and concurrent-writer stress; exactly-once processing; complete real-world photo/carousel acquisition; a complete new-skill proposal -> approved installation -> functional verification; universal source availability; future Hermes compatibility. Static template/contract tests cannot establish these runtime properties.
