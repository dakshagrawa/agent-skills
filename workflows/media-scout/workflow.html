SCOUT · the front desk

Extract, save, preview, discuss corrections and relay approvals/results. May gather skill discovery leads—not decide what your setup needs.

DEFAULT · the decision-maker

Understanding, learning, research, relevance and optional skills/actions. Uses your context; implements and verifies changes only after specific approval.

YOU · approval for changes

Sharing media triggers review automatically. Approve only the exact consequential change. Silence or asking for a proposal never authorizes execution.

Persistence and retention

  • One canonical JSON catalog record; detailed Markdown evidence and a separate heavy cache.
  • Catalog records do not auto-expire. Detailed evidence: 90 days from explicit user revisit, otherwise extraction. Heavy cache: 7 days.
  • Pinned/active-review evidence is protected. Background lookup does not extend retention.
  • Source deployment: daily bounded cleanup was qualified on fixtures and enabled. Public templates start REPORT-ONLY; explicit local consent and qualification are required.

Reliability and accepted limits

  • Hourly browser-based missed-message discovery remains PAUSED, as accepted; no Scout Discord browser login was added.
  • Native reconnect recovery is configured and bounded; it is not a periodic full-history guarantee.
  • Native queued-task quota retries reuse tasks; actual quota-outage recovery is not live-tested.
  • Default is a separate worker—not a second bot that must join Scout’s thread. No new Discord permissions are needed for this workflow.
Knowledge is retained as attributed searchable notes, not blind user-memory ingestion or automatic injection into every existing chat. Security boundary: source content is untrusted; official/native reuse is preferred.
